# Contributing Guidelines

Thank you for your interest in contributing to this sample. This repository
accompanies an AWS Database Blog post and exists to demonstrate a specific
workflow; it is not a long-lived open source project. We welcome bug reports and
small fixes via issues and pull requests.

## Reporting Bugs/Feature Requests

Use the GitHub issue tracker to report bugs or suggest fixes. When filing an
issue, please check existing open and recently closed issues, and include as
much detail as you can:

- A reproducible test case or series of steps
- The version of the code being used
- Any modifications you've made relevant to the bug
- Anything unusual about your environment or deployment

## Contributing via Pull Requests

Before sending a pull request, please:

1. Confirm you're working against the latest source on the *main* branch.
2. Check existing open and recently merged pull requests to avoid duplicating effort.
3. Open an issue to discuss any significant change before investing time.

To send a pull request:

1. Fork the repository.
2. Modify the source, focusing on the specific change you are contributing.
3. Ensure local tests/deployments pass.
4. Commit to your fork using clear commit messages.
5. Send a pull request answering any default questions in the PR template.

## Code of Conduct

This project has adopted the
[Amazon Open Source Code of Conduct](https://aws.github.io/code-of-conduct).
See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Security issue notifications

If you discover a potential security issue, please notify AWS Security via the
[vulnerability reporting page](http://aws.amazon.com/security/vulnerability-reporting/).
Please do **not** create a public GitHub issue for security findings.
